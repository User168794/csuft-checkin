# 平安打卡 · csuft-checkin

> 中南林业科技大学学工部「平安打卡」的 Android 自动化客户端 —— 手机号短信登录一次，之后全自动续期与打卡；每日定时窗口自动执行 + 结果复核通知。纯 HTTP 实现：运行时无需微信、也不需要服务器。

个人自用工具，仅供学习交流。**使用须知与免责声明见文末。**

## ✨ 功能特性

**登录与续期**
- 🔐 手机号短信登录（学校官方 CAS 免密通道），只需一次验证码
- ♻️ `refresh_token` 滑动自动续期 —— 之后长期无需再登录

**自动打卡**
- ⏰ 打卡窗口 21:00–22:30，四班次自动尝试：21:05 / 21:35 / 22:05 / 22:25（精确闹钟调度）
- 🚫 已打卡自动跳过、静默不打扰；每天只允许打卡一次
- 🎯 提交坐标每次现算（两级随机），不是固定坐标

**运行保障**
- 📋 运行日志（诊断）：打开 / 关闭 / 退后台 / 心跳 / 班次触发 / 静默原因 / 结果，全量可查
- 💓 后台心跳（每 15 分钟）：万一被系统清理，也能从日志定位"活到几点"
- 🔔 状态栏通知：打卡结果 / 登录失效提醒 / 22:35 复核判词
- ⚡ 免杀引导：电池优化白名单（一键申请）+ 自启动 / 后台高耗电 / 最近任务锁定（本地化引导）

## ⚙️ 工作原理

### 1️⃣ 登录链路（CAS 短信免密）

```text
手机号 ──► 打开 CAS 登录页（取 execution）
       ──► passwordlessTokenSend      发送短信验证码
       ──► 提交短信码（_eventId=submitPasswordlessToken）→ 获得 TGC
       ──► 票据跳转链换票（ST）→ 得到 tgc
       ──► OAuth2 换发 access_token + refresh_token
```

- 这是学校的**官方免密登录通道**，App 内 1:1 复刻 —— 不涉及抓包 / 证书 / 代理
- 换票跳转链存在服务端随机抖动 → 客户端内置**多轮重试与退避**（约 1 分钟内自愈）
- 之后每次打卡前用 `refresh_token` 自动换新令牌（滑动更换，链式可用）

### 2️⃣ 打卡链路（三个接口）

| 步骤 | 接口 | 作用 |
| --- | --- | --- |
| ① 查 | `dormSignRecord/getOne` | 今日是否已打卡（已打卡直接跳过） |
| ② 拉 | `dormSignTask/getTaskByIdForApp` | 任务详情（允许半径 `locationAccuracy`、`roomId` 等） |
| ③ 交 | `dormSignRecord/stuSign` | 提交打卡（实时签名 + 坐标 + 日期），失败自动重试 ≤ 4 次 |

提交后立即复查确认，结果写入运行日志与「最近记录」。

### 3️⃣ 坐标策略（两级随机）

```text
宿舍登记点（原点）
  └─ ① 以原点为圆心，300m 圆内均匀随机 → P1
       └─ ② 以 P1 为圆心，500m 圆内均匀随机 → P2（最终提交 P2）
```

- 距登记点最远约 800m；服务端允许半径 = 任务详情 `locationAccuracy`（实测 2000m，余量 2.5×）
- 每次提交**现算**，不存在固定坐标模式

### 4️⃣ 定时调度

- 窗口 21:00–22:30；班次 21:05 / 21:35 / 22:05 / 22:25；22:35 复核
- `AlarmManager` 精确闹钟 + 开机自动重挂 + 心跳兜底
- 「每日自动打卡」「窗口结束后复核」两个开关默认开启

## 🔏 请求签名（FlySource-sign）

每个请求实时计算签名：

```text
inner = md5( 毫秒时间戳 + token )
sign  = md5( 相对路径 + "?sign=" + inner ) + "1." + base64( 毫秒时间戳 )
```

| 请求头 | 值 | 备注 |
| --- | --- | --- |
| `FlySource-Auth` | access_token | **原始值**，不加 `Bearer ` 前缀 |
| `FlySource-sign` | 上式现算 | 每次请求重新计算 |
| `Authorization` | `Basic <客户端级常量>` | 网页客户端级公共凭据（非个人，见 `Secrets.java`） |
| `User-Agent` | 完整浏览器串 | 不完整 UA 会被 WAF 拒绝（实测 400） |

请求体里的 `stuTaskId` 为**字段防篡改值**：

```text
stuTaskId = md5( {"latitude":"…","longitude":"…","locationAccuracy":"…",
                  "signDate":"…","taskId":"…","fileId":""} )
```

> 三个易错点：① 签名用**相对路径**且**剔除 query**；② token 用原始值（不要 bearer 前缀）；③ 时间戳为**毫秒**。

## 🚶 走过的路：我们为什么放弃了「小程序抓包逆向」？

本项目**早期的实现方式，正是同校其他软件现在还在用的那条路** —— 抓包 + 小程序逆向：

```text
① 抓包    对「中南林学工」小程序的完整打卡会话抓包（手机代理 + 证书）
② 逆向    解密小程序包体，逐行还原其请求签名拦截器
③ 复刻    得到请求签名算法（FlySource-sign，见上节）与全部业务接口
④ 复用    从抓到的会话里提取 FlySource-Auth 令牌（JWT），交由脚本 / App 打卡
```

早期版本（v1.x）就是这么运行的：令牌内置进 App（自用版）、手动粘贴（分享版），签名算法也正来自这次逆向。它能跑通，但有几个绕不过去的问题：

| # | 问题 | 具体表现 |
| --- | --- | --- |
| 1 | **令牌短命** | JWT 约 10–20 天过期，必须重新抓包采集 |
| 2 | **使用门槛高** | 使用者要装证书、开代理、在微信里走一遍登录流程 —— 对普通同学几乎不可能 |
| 3 | **环境脆弱** | 微信版本更新、小程序加密升级，逆向链路就要返工 |
| 4 | **凭据外流** | 想给同学用，就得把会话令牌交给对方 / 被采集 |
| 5 | **自动采集也不易** | 为此调研过「令牌录制器」（App 内 VpnService 全局抓包 + 本地 MITM 自动取令牌），卡在 Android 证书信任限制与微信加密保护上，做不干净 |

**转折点**：在系统梳理学校的登录方式时发现，CAS 提供**官方短信免密登录**（`passwordlessTokenSend`）—— 「拿令牌」根本不需要抓包，App 内用「手机号 + 短信验证码」就能走完整个 OAuth 流程。

于是 **v2.0 起彻底换轨**：

- ✅ 去掉抓包 / 证书 / 代理 —— 登录走官方标准流程
- ✅ 去掉 10–20 天的令牌重采 —— `refresh_token` 滑动续期
- ✅ 去掉「把令牌交给别人」 —— 凭据只留在本人手机
- 签名算法继续沿用（它属于服务端协议层，与客户端形态无关）

> 一句话：那条老路我们是**走通之后主动放弃的** —— 不是能力问题，而是它的「维护成本 / 使用门槛 / 隐私代价」不适合做成给普通人用的小工具。

## 为什么我们不怕二次认证以及完全 0 门槛自动化？（与同校其他软件相比）

学校账号启用了**短信二次认证**。同校常见的另一条路线（采集微信小程序会话）因此走不通「学号 + 密码」，只能抓包把会话 token 采出来复用：使用者要配合装证书、开代理、被别人采集一次，而且 **token 约 18–20 天过期，需要重新采集**。

我们直接走 **CAS 官方短信登录** —— 「二次认证」在我们这里就是「唯一一次认证」：

| 对比项 | 本项目 | 常见路线（小程序会话采集） |
| --- | --- | --- |
| 登录方式 | 官方短信免密登录（本人一次） | 抓包采集小程序会话 |
| 证书 / 代理 | **不需要** | 需要（临时安装） |
| 长期维护 | **refresh_token 自动续期** | token 约 18–20 天过期需重采 |
| 凭据存放 | **只在本人手机** | 部署方服务器集中保管 |
| 请求出口 | **每台手机独立** | 默认同一服务器 IP |
| 提交坐标 | **两级随机（每次不同）** | 多为固定坐标 |

一句话：**装好 App、收一条本人短信，之后全自动。**

> 两条路线没有绝对好坏：服务器形态也有它的长处（手机不在线也能打卡、便于批量管理）。本项目按「个人自用、隐私优先、免维护」的目标取舍。

## 📱 使用说明

1. 安装 APK（构建产物不随仓库分发 —— 自行构建，或向分享者索取）
2. 打开 App →「手机号登录」→ 输入手机号、获取并填写短信验证码（仅此一次）
3. 保持「每日自动打卡」「窗口结束后复核」两个开关开启
4. 按界面引导完成免杀设置（电池优化白名单 / 自启动 / 后台高耗电 / 最近任务锁定），确保到点能唤醒

## 🔨 从源码构建

依赖：`bash` + JDK（javac，d8 运行需 java）+ Android SDK（`build-tools 36.1.0`、`platforms/android-36.1`）

```bash
# 机器路径与脚本默认不同时，用环境变量覆盖：
export ANDROID_SDK="C:/Users/<你的用户名>/AppData/Local/Android/Sdk"
export JAVA_BIN="/d/JAVA/bin"                 # 含 javac 的目录
# export CHECKIN_OUT_DIR="/path/to/output"    # 产物输出目录（默认 = 仓库上一级）

bash build.sh
# 产物：平安打卡-v<版本>.apk（首次构建会自动生成 debug.keystore）
```

流水线为纯手工 `aapt2 compile/link → javac → d8 → zip 注入 classes.dex → zipalign → apksigner`，无需 gradle。
