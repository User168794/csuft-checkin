# 平安打卡 · csuft-checkin

> 中南林业科技大学学工部「平安打卡」的 Android 自动化客户端 —— 手机号短信登录一次，之后全自动续期与打卡；每日定时窗口自动执行 + 结果复核通知；纯 HTTP 实现，运行时无需微信/小程序。

个人自用工具，仅供学习交流。**使用须知与免责声明见文末。**

## ✨ 功能特性

- 🔐 **手机号短信登录**（学校 CAS 统一认证）：只需一次验证码登录；之后 `refresh_token` 滑动续期，打卡前自动完成，用户无感
- ⏰ **每日自动打卡**：21:05 / 21:35 / 22:05 / 22:25 四个班次自动尝试（受系统精确闹钟调度），已打卡自动跳过、静默不打扰
- ✅ **窗口结束复核**：22:35 自动查询并通知最终判词（是否打卡成功）
- 🎯 **坐标随机化**：提交坐标 = 以宿舍登记点为原点的两级随机（300 m → 500 m），每次提交都不同
- 📋 **运行日志（诊断）+ 后台心跳**：打开/关闭/退后台/心跳/班次触发/静默跳过原因/结果全量记录，界面内可查看
- 🔕 **状态栏通知**：打卡结果、登录失效提醒、主动退出提示
- ⚡ **免杀引导**：一键申请电池优化白名单 + 图文本地化引导（自启动 / 后台高耗电 / 最近任务锁定）

## ⚙️ 工作原理（简版）

1. **登录**：CAS 短信登录（`cas.csuft.edu.cn`）→ 拿 TGC → 换票（`ST`）→ OAuth2 换发 `access_token` / `refresh_token`。换票链路服务端存在随机抖动，客户端带自动重试与退避
2. **打卡**：三个 HTTP 接口 —— 查询今日记录 / 拉取任务详情 / 提交打卡；每个请求带实时签名 `FlySource-sign = md5(path + "?sign=" + md5(毫秒时间戳 + token)) + "1." + base64(时间戳)`
3. **坐标**：每次提交现算两级随机坐标；服务端允许范围为任务详情中的 `locationAccuracy`
4. **调度**：`AlarmManager` 精确闹钟 + 开机重挂 + 后台心跳兜底；每天只允许打卡一次

## 为什么我们不怕二次认证以及完全 0 门槛自动化？（与同校其他软件相比）

同校公开的同类工具，常见的一条实现路线是**采集微信小程序会话（token）**：因为学校账号在接口层启用了**短信二次认证**，`学号 + 密码` 换 token 走不通，只能先在小程序里登录，再用抓包工具（证书 + 代理）把这次会话的 token 采出来，放到服务器上长期复用。

这条路能跑通，但代价不小：使用者要配合装证书、开代理、被别人"采集"一次；**token 约 18–20 天过期，到期还得重新采集**；token 通常交给部署方（管理员）集中保管；多用户版本还会产生"全班打卡都来自同一台服务器 IP"的批量特征。

**我们的路线完全不同——直接走学校 CAS 的官方短信登录，把"二次认证"变成"唯一一次认证"。**

1. **不绕认证，我们走的就是官方认证本身**：`cas.csuft.edu.cn` 提供「手机号 + 短信验证码」免密登录（`passwordlessTokenSend`），这本身就是学校标准登录流程。我们在 App 内完整复刻了它 —— 因此 **不需要密码、不需要抓包、不需要证书、不需要代理、不需要任何人帮忙操作**。
2. **一次登录、长期自动（核心优势）**：登录成功后持 OAuth `access_token` + `refresh_token`，打卡前自动用 `refresh_token` 滑动续期（换发新 access + 新 refresh，链式可用）。**没有"每十几天重新采集一次"的维护成本。**
3. **完全 0 门槛**：使用者侧只有两步 —— **装好 App、收一条本人短信**。之后每天自动打卡 + 22:35 复核通知。不需要电脑、不需要服务器、不需要"授权采集工具"。
4. **凭据只在你自己手机上**：token 仅存于 App 私有存储，不上传任何服务器、不经过任何第三方 —— 相比"把会话交给部署方集中保管"，少一层隐私与滥用风险。
5. **每台手机独立出口**：打卡请求从每个人的手机、各自的网络发出，与真人手机行为一致；不存在"一班人同一 IP"的中心化批量特征。
6. **坐标两级随机**：每次提交现算坐标（以宿舍登记点为原点做两级随机，距其约 2~791 m），而不是固定坐标，更接近真实定位抖动。

| 对比项 | 本项目（CAS 短信登录路线） | 常见路线（小程序会话采集） |
| --- | --- | --- |
| 登录方式 | 官方短信免密登录（本人一次） | 抓包采集小程序会话 |
| 需要密码 | 否 | 否（但需他人引导采集） |
| 证书 / 代理 | **不需要** | 需要（临时安装） |
| 长期维护 | **refresh_token 自动续期** | token 约 18–20 天过期需重采 |
| 凭据存放 | **只在本人手机** | 部署方服务器集中保管 |
| 请求出口 | **每台手机独立** | 默认同一服务器 IP |
| 提交坐标 | **两级随机（每次不同）** | 多为固定坐标 |

> 客观地说，服务器路线也有它的长处（手机不在线也能打卡、便于一对多批量管理）。本项目按 **「个人自用、隐私优先、免维护」** 的目标做的取舍 —— 两条路线没有绝对好坏，只有适不适合。

## 📱 使用说明

1. 安装 APK（构建产物不随仓库分发——自行构建，或向分享者索取）
2. 打开 App → 「手机号登录」→ 输入手机号、获取并填写短信验证码（仅此一次）
3. 保持「每日自动打卡」「窗口结束后复核」两个开关开启
4. 按界面引导完成免杀设置（电池优化白名单 / 自启动 / 后台高耗电 / 最近任务锁定），确保到点能唤醒

## 🔨 从源码构建

依赖：`bash` + JDK（javac via d8 运行需 java）+ Android SDK（`build-tools 36.1.0`、`platforms/android-36.1`）

```bash
# 如机器路径与脚本默认不同，用环境变量覆盖：
export ANDROID_SDK="C:/Users/ABC/AppData/Local/Android/Sdk"
export JAVA_BIN="/d/JAVA/bin"          # 含 javac 的目录
# export CHECKIN_OUT_DIR="/path/to/output"   # 产物输出目录（默认=仓库上一级）

bash build.sh
# 产物：平安打卡-v<版本>.apk（首次构建会自动生成 debug.keystore）
```

流水线纯手工：`aapt2 compile/link → javac → d8 → zip 注入 classes.dex → zipalign → apksigner`，无需 gradle。
